# Quantica — working on this project

Quantica (**quanticaedu.com**) is a problem-first math education product by solo founder
Aayan Khare. Students learn by solving guided problems with an AI tutor ("Milo") on every
problem, in the spirit of AoPS rigor delivered the way Brilliant delivers it. Free while in
early access.

## Architecture in one screen

- **`landing.html`** (~450KB, single file, no build step) is the whole front end: a
  marketing region (class-scoped `.wmb`), then the course app SPA after `<!-- SIGNUP -->`.
  It holds the app shell, rewards/XP engine, the Milo tutor UI, PSETS, auth, analytics, and
  history-based navigation. It does NOT hold lesson content.
- **`data/lessons-<course>.js`** is what the app actually loads, one generated chunk per
  course, each assigning into `window.__COURSEDATA`. The default course is loaded
  synchronously; every other course is loaded with `defer` so a first visit does not parse a
  course nobody opened. `data/lessons.js` is still generated as the combined bundle, but
  only `tools/gen_seo_pages.py` reads it now. All of them come from `tools/build_lessons.py`
  via `lessons/<course>/chapter-*.json`. Never hand-edit any of them.
  **Deferred-course trap.** A deferred chunk has not executed while the inline scripts are
  parsing, so anything that reads a non-default course's lessons at parse time sees nothing.
  Read it through a getter, or wait for `DOMContentLoaded` (deferred scripts always finish
  first). Two places already got this wrong and are fixed in `landing.html`, `COURSE_REG`'s
  `lessons` and the boot restore of the last-used course; copying either pattern is fine,
  capturing `__COURSEDATA.<course>` into a variable at parse time is not.
- **`lessons/<course>/`** holds the source of truth: `chapter-N.json` (content) + `toc.json`
  (index). Courses today: `prealgebra`, `algebra1`.
- **`prealgebra/*.html`** are static SEO pages, one per lesson, generated by
  `tools/gen_seo_pages.py`.
- **`functions/`** is the Firebase Cloud Functions backend (Stripe checkout, Firestore sync).
- Milo runs on a Cloudflare Worker (`TUTOR_WORKER` in `landing.html`). Its source IS in this
  repo at `tutor-worker/milo-worker.js`, deployed to Cloudflare by hand, and it is on the
  `firebase.json` ignore list because it holds the full system prompt and the answer-reveal
  gate. It was publicly served from quanticaedu.com until 2026-08-14 because it was not.
- Hosting is Firebase (`firebase.json`, `cleanUrls`). **`/` rewrites to
  `/paths/landing.html`, a separate 55KB marketing page, NOT to the app.** The app is
  served at **`https://quanticaedu.com/landing`**, and `cleanUrls` 301s `/landing.html`
  to `/landing`. So verify a shipped app change with `curl -sL https://quanticaedu.com/landing`;
  curling `/` returns the marketing page and makes a good deploy look like a failed one.
  Lesson content is separate and lives at `/data/lessons-<course>.js`, which curls directly.

## Golden rules

**Security (standing, do not violate):**
- **Never commit, read, or touch `functions/.env`** — it holds the live Stripe secret key.
- **Deploy hosting only: `firebase deploy --only hosting`.** Never deploy functions.
- Firestore rules (console only, no `firestore.rules` in this repo) restrict each user to
  their own `users/{uid}` and `users/{uid}/state/*`, EXCEPT `state/subscription`, which is
  client-read-only. Only the Stripe webhook writes it, through the Admin SDK, which bypasses
  rules. Locked 2026-08-15 after a probe showed any signed-in user could previously
  `set({type:'paid'})` on their own subscription doc. If a client feature ever needs a new
  per-user doc, write it under `state/` with any name except `subscription` and the rules
  already allow it.

**Build + deploy loop for any content or app change:**
1. Edit `lessons/<course>/chapter-N.json` (content) or `landing.html` (app).
2. `python3 tools/build_lessons.py` (if you touched any chapter JSON).
3. Preview-test in the browser (see below); expect **0 `.katex-error`**.
4. `git commit` → `git push origin main` → `firebase deploy --only hosting`.
5. `curl` the live page, or the live `data/lessons-<course>.js` **for the course you
   touched**. Curling the combined `data/lessons.js` proves nothing about the app now, since
   the app no longer loads it.

**Tutor naming:** the tutor is **Milo**, in every course and on every surface. Earlier
per-course names (Sprout for Prealgebra, Cove for Algebra I) were retired on 2026-07-30.
CSS identifiers and theme variables still carry the old words; those are internal and
drive the per-course palette, so leave them alone. Only user-facing strings say Milo.

**Voice (chat and content):** No em-dashes. Almost no colons in prose. Plain, natural,
AoPS-direct writing, never a poetic/abstract register. Full detail in `docs/AUTHORING.md`
and memory `no-em-dashes`.

**Answer verification:** every math answer in a lesson or PSET is machine-verified (exact
`Fraction` arithmetic, brute-force search where relevant) before it is committed. No
exceptions.

## Common tasks

- **Author a lesson** → `docs/AUTHORING.md` and `docs/HANDOFF.md`. Copy the Workflow template
  `tools/author_lesson.workflow.js` (a SPEC + OUTLINE swap; worked examples in
  `tools/lesson-specs/`), then verify with `tools/check_lesson.py`, then
  `tools/finalize_lesson.py`, then build + deploy.
- **Verify content** → `tools/check_lesson.py` for a lesson, `tools/check_pset.py` for a problem
  set. Both must report 0 issues before a build. They catch what `finalize_lesson.py` does not.
- **Coverage vs the reference text** → `docs/reference-coverage-map.md` (chapters 6, 7, 8 mapped).
- **Add a course** → `lessons/<slug>/toc.json` + `chapter-*.json`, add the slug to `COURSES`
  in `tools/build_lessons.py`, and register it in `COURSE_REG` in `landing.html`. The engine
  is course-agnostic; a course with live lessons auto-unlocks its in-app tab.
- **Make a short video** → `tools/shorts/README.md`. Python renders 1080x1920 frames,
  ffmpeg encodes, ElevenLabs narrates. Write the words first and move the pictures to fit.
- **Regenerate SEO pages** → `python3 tools/gen_seo_pages.py <course>`.
- **Preview** → `mcp preview_start` with `.claude/launch.json` (static server on :8743), then
  open `/landing.html?course=<c>&lesson=<k>`. Note the plain static server does not apply the
  Firebase `/` rewrite, so use `/landing.html` explicitly.
