## The outage

`paths/home.html` builds its entire roadmap inside
`fetch('/lessons/<course>/toc.json')`. On 2026-08-04 commit `41f9c0c` added `lessons/**` to
the `firebase.json` ignore list, reasoning that "nothing served depends on those paths". That
fetch did. The URL began returning the 404 HTML page, `r.json()` threw on it, execution fell
into the catch, `renderAll()` never ran, and every visit rendered one grey error line reading
"Could not load the course outline. Make sure the site is served over http".

It is not a quiet corner. The blog nav links there, the coursebar Home button goes there,
exiting a lesson lands there, and `?signin=1` redirects there.

Fixed in `4fc7a60`. `lessons/` stays unpublished, which is what `41f9c0c` wanted.
`tools/build_lessons.py` now also emits `data/toc-<course>.json`, and `data/` is deployed. The
fetch checks `r.ok` before parsing, so the next missing file raises `toc 404 for algebra1`
rather than a SyntaxError that reads like a parse bug.

**Why one account seemed fine and the other did not.** The first was an already-restored
session, so no `?signin=1` in the URL, no redirect, and it stayed in the app at `/landing`. The
second was a fresh sign-in, which always carries `?signin=1`, so it was thrown at the dead
page. "Could not get to the home page" is a literal description of that.

## Paywall

Code-complete and enforced, still switched off. What changed in `6c20275`:

- `showLesson`, `openPSet` and `openPractice` all gate now. An unwritten or out-of-range
  chapter fails closed rather than falling through.
- A blocked visitor gets a real screen naming the chapter, what Pro includes and a sign-in
  link, rather than a bounce to the contents that reads as the site being broken.
- The subscription doc is watched with `onSnapshot`, so the Stripe webhook write unlocks the
  course in place. A one-shot read runs alongside purely to settle first paint. Before this, a
  customer who won the race against the webhook saw "welcome to Quantica Pro" on top of a
  locked course with no way out but a reload they had no reason to try.
- Every failure path errs toward the customer. A read that fails or times out settles to
  `unknown`, which grants. Denying there would strip a paying subscriber over a network blip.
- `isLegacyUser` uses `<=`, so an account created in the same second as the switch is
  grandfathered rather than charged.
- A deep link that arrives before access resolves is parked and replayed, not shown a paywall
  for content the person already owns.
- `startCheckout` refuses to sell a second subscription to someone who already has one, which
  matters while there is still no billing portal.
- If the webhook never confirms, the customer is told after a minute, and told not to pay
  again.

### Before switching on

Four checks, none of which can be done from inside the repo.

1. **Run one real card.** `startCheckout` does not check `paywallOn`, so
   `/landing?upgrade=monthly` works right now with charging off. Proof to look for, in order:
   Stripe shows **$14.99**; you land back on the **app**, title "Quantica | Master
   Mathematics by Doing Mathematics", not the marketing page; `users/{uid}/state/subscription`
   shows `type:"paid"` within seconds; the course unlocks with no reload.
2. **Confirm `APP_URL` is `https://quanticaedu.com/landing`**, no trailing slash. `/` rewrites
   to the marketing page, so a bare-origin value drops every buyer on a pricing page and makes
   the whole `?payment=success` path dead code. Read it in the Firebase console. Do not open
   `functions/.env`.
3. **Confirm the Stripe webhook**, live mode, is subscribed to `customer.subscription.created`,
   `updated` and `deleted`. The handler returns 200 for events it ignores, so an endpoint
   subscribed only to `checkout.session.completed`, which is what Stripe's own quickstart
   suggests, records 100% successful deliveries while `type:"paid"` is never written for
   anyone.
4. **Confirm the Firestore rules** do not let a client write its own `users/{uid}/state/
   subscription`. There is no `firestore.rules` in this repo and `firebase.json` declares only
   hosting and functions, so the rules exist only in the console and are invisible here. Test
   it by running a `.set({type:'paid'})` from the browser console as a normal account. It must
   throw permission-denied.

### Known and deliberately not fixed

- **No billing portal.** `terms.html` says a subscription can be cancelled "through your
  account settings". There are no account settings that do this. Fixing it properly needs a
  `createPortalSession` callable and therefore a functions deploy, which this repo never does.
  The cheap alternative is to name email as the cancellation route.
- **`past_due` locks a paying customer out instantly.** `functions/index.js` treats only
  `active` and `trialing` as paid. Stripe retries a failed renewal for weeks and the
  subscription is still theirs. Nobody has a renewal for 30 days, so this is not urgent, but
  it needs a functions deploy.
- **The yearly plan has never been exercised.** No in-app path can even select it: the click
  handlers pass the DOM Event as the plan argument and anything that is not the literal string
  `'yearly'` normalises to monthly. The $99.99 button on the marketing page is the only route.
- **The gate is client-side.** `data/lessons-algebra1.js` is 1.4MB of public JSON, `Date.now()`
  is the device clock, and `window._access` is a page global. Anyone technical gets everything
  free. This is an accepted architectural limit, not a bug, and it should be a conscious
  decision rather than a later discovery.

## Hard-won this session

- **A 200 does not mean a page works.** `/paths/home` returned 200 the entire time it was
  broken, because the failure was in a fetch inside the page. Verify the asset the page
  fetches, not just the page.
- **`cleanUrls` 301s, and curl does not follow by default.** Checking the deployed
  `/paths/home.html` returned zero matches for every string, which looked exactly like a
  failed deploy. It was the redirect stub. `curl -L`, always. Same family as the `/` versus
  `/landing` trap already in CLAUDE.md.
- **Anything fetched at runtime must live in `data/`.** `lessons/`, `docs/` and `tools/` are on
  the `firebase.json` ignore list. Local testing cannot catch this, because a static server
  happily serves ignored directories.
- **Generated files that ship must be `git add`ed.** A deploy uploads from the working tree, so
  an untracked generated asset deploys green and then vanishes on the next clean checkout.
  `data/toc-*.json` nearly shipped that way.
- **"Switzer dropped entirely" is false for `landing.html`.** It is used 92 times there,
  including `body`, and still fetched. That claim in the previous handoff applies to the
  marketing and catalog pages only. Small UI labels in the app are Switzer against Chillax
  headings on purpose.
- **Measure, do not copy counts forward.** Every number in the previous handoff that could be
  checked was wrong. Derive from `lessons/<course>/chapter-*.json` or from a browser.
