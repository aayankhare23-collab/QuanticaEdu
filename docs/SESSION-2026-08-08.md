## Paywall

- Live-ready but **OFF**. `window.PAYWALL_LIVE_AT` in landing.html is `2099-01-01`.
- Turning it on is editing that one date. Before it, everything is free; from it, the gate
  applies and every account created BEFORE it is grandfathered. One constant drives both, so
  the FAQ promise cannot drift from the switch-on moment.
- `isAccessGranted` is live code, not a commented draft, so it cannot rot.
- Verified by simulating the switch as already thrown: legacy and paid keep chapter 5, new
  free / signed-out / expired trial are gated, chapter 1 free for all.
- **Blocking:** nobody has completed a real-card checkout. If the Stripe webhook is
  misconfigured, `type:"paid"` is never written and a paying customer stays gated. The proof
  is `users/{uid}/state/subscription` showing `type: "paid"` in Firestore.
- Fixed this session: the catch branch of the subscription load set `type:'none'`
  unconditionally, so any legacy account whose Firestore read failed was silently demoted.

## Hard-won this session

- The app assumes every arrival is a student starting a lesson. Buyers are a different kind
  of arrival, and that mismatch produced four separate bugs in the checkout flow.
- `.wmb` is the hidden legacy region inside landing.html. Code that targets it runs and
  renders nowhere. That is why signed-in state was invisible, and it is the first place to
  look when something "does nothing".
- Verify against the path users take, not the path that is convenient to reach. Localhost
  resolves auth signed-out, which is a different branch from a real signed-in session, and
  several bugs survived multiple fixes because of it.
